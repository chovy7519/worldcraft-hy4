# 城市要素关系契约与规则审查（v1.3.0 规则层）

> 触发点：使用者观察到「广场和绿地压在道路上」，并指出「城市是一个整体，是会互相影响的」。
> 本文是审查记录 + 修复后的规则说明，不是功能介绍。**先写清关系，再谈表现。**

## 1. 审查结论：观察属实，且比看起来严重

`npx vite-node scripts/diagnose-spatial.ts` 用布尔交集逐图层量化（不是看图）：

| 图层 | 修复前与道路带重叠 | 修复后 |
| --- | --- | --- |
| 公园 / 广场（默认 400 m） | **57 / 57 个，11,169 m²，占公园面积 28.3%** | 0 |
| 广场（其中） | 15 个，3,075 m² | 0 |
| 公园比例 30% | 129 / 131 个，23,744 m² | 0 |
| 中央公园 3×3 | 45 / 45 个，9,498 m² | 0 |
| E1 水面（开启时） | 395 m² | 0 |
| 建筑 | 0 栋 | 0 栋 |
| 乔木 | 0 株路缘净距为负 | 0 株 |
| **空间校验** | **全部 PASS** | **全部 PASS** |

两件事值得单独指出：

1. **不是渲染错觉。** 公园面 `y=0.14` 高于道路顶面 `y=0.10`，高度差只是让压路更明显；几何上公园多边形确实与道路带四边形相交 28.3%。你说的「不在一个图层上」是准确的直觉，但问题的根源在数据层。
2. **校验器当时是 PASS 的。** 它检查了「公园 ⊂ 所属地块」「公园不与可建地块重叠」，唯独没有「公园 vs 道路」这一对。建筑与树都被约束、公园与广场没有——**规则不一致**，不是某个图层画歪了。

## 2. 根因：关系散落在各阶段，没有单一事实来源

修复前的实际状况：

| 要素 | 临路退界在哪算 | 用什么参数 | 谁校验 |
| --- | --- | --- | --- |
| 建筑 | `stageBuildings::edgeBuffersOf()` | `parcels.setback` + 硬编码 `0.5` | `BUILDING_ROAD_OVERLAP` |
| 乔木 | `stageTrees` | `trees.roadSetback` | `TREE_ROAD_CLEARANCE` |
| 公园 / 广场 | **无** | `parks.inset` 只用于树位净距 | **无** |
| 水面 | 无（只做岸线内缩） | `extensions.bankSetback` | 曾加错口径后移除 |

`stageParks.ts` 里 `finalPoly = g.polygon` 直接把**完整地块多边形**当作绿地范围。而地块红线本身是压在道路带内的（`parcels.gap` 只是地块间缝隙，不是临路退界）——建筑靠额外退界避让，绿地没有，于是必然压路。

更本质的问题：**阶段之间是数据流依赖，不是空间约束依赖**。`STAGE_GRAPH` 声明的是「谁读谁的输出」，没有声明「谁必须避让谁、避让多少、由哪个参数驱动」。所以改一个参数不会传导，加一个新要素不知道该遵守什么。

## 3. 修复：把关系写成契约

新增 `src/core/spatialRules.ts`，收拢三件事：

- **`RELATION_MATRIX`**：19 条显式关系，声明主体 / 客体 / 关系类型 / 驱动参数 / 校验 code。关系类型共 7 种：`defines`、`containedBy`、`setbackFrom`、`disjointWith`、`follows`、`avoids`、`drives`。新增要素不登记，`relations.test.ts` 会失败。
- **`clearanceFor()` + `setbackFromBand()`**：全体要素共用的退界量，**复用已有参数**，不新增「同一件事两个旋钮」。
- **`bandPolygon()` / `setbackFromRoads()`**：生成侧与校验侧共用的道路带几何口径，杜绝「校验说 PASS、画面上压路」。

### 关系矩阵（摘要）

| 主体 → 客体 | 关系 | 参数 / 校验 |
| --- | --- | --- |
| 道路 → 地块 | defines | 面积守恒 `FACE_AREA_MISMATCH` |
| 地块 → 道路 | containedBy | 红线允许压在道路带内（历史口径，不改） |
| 建筑 → 道路 | setbackFrom | `parcels.setback` / `BUILDING_ROAD_OVERLAP` |
| 建筑 → 地块 | containedBy | `BUILDING_OUTSIDE_POLYGON` |
| 建筑 → 公园 | disjointWith | `PARK_BUILT_PARCEL_OVERLAP` |
| **公园 / 广场 → 道路** | **setbackFrom** | **`parks.inset` / `PARK_ROAD_OVERLAP`（新增）** |
| 公园 → 地块 | containedBy | `PARK_OUTSIDE_POLYGON` |
| **水面 → 道路** | **setbackFrom** | **`extensions.bankSetback` / `WATER_ROAD_OVERLAP`（新增）** |
| 乔木 → 道路 / 建筑 | setbackFrom / avoids | `trees.roadSetback` / `TREE_ROAD_CLEARANCE` |
| **车辆 → 道路** | **follows** | `mobility.laneOffset` / `VEHICLE_OFF_ROAD` |
| **行人 → 道路 / 公园** | **follows** | `mobility.sidewalkWidth` / `PEDESTRIAN_ON_ROAD` |
| **行人 → 建筑 / 水面** | **avoids** | `PEDESTRIAN_INSIDE_BUILDING` / `PEDESTRIAN_IN_WATER` |
| 道路 / 公园 → 车流 / 人流 | drives | 配额由道路等级、建筑密度、公园面积决定 |

### 统一退界的传导链（最关键的改动）

```
mobility.sidewalkWidth
   └─ buildingRoadClearance() = max(0.5, sidewalkWidth + 0.4)
        ├─ 建筑临路净距（edgeBuffersOf）→ 建筑数量 / 足迹变化
        ├─ 步道中心位置（sidewalkOffsetWithin）→ 行人路径变化
        └─ 空间校验（PEDESTRIAN_INSIDE_BUILDING）→ 一处不合法当场报错
```

修复前这里硬编码 `0.5 m`，建筑与 1.8 m 宽的人行道争同一条 1 m 带，导致**行人路径穿楼 40 处**。把步道宽度调到 3.5 m，建筑会自动再退 1.7 m。这就是「城市是一个整体」在工程上的落点：一个参数改动，通过契约传导到三个图层和一套校验，而不是各改各的。

## 4. 修复代价（不粉饰）

| 项 | 修复前 | 修复后 | 变化 |
| --- | --- | --- | --- |
| 公园 / 广场总面积 | 39,455 m² | 24,943 m² | **−36.8%** |
| 乔木总数 | 777 株 | 814 株 | +37 株 |
| E1 水面面积（开启时） | 7,344 m² | 4,609 m² | −37.2% |

绿地面积下降是**真实的空间代价**，不是视觉缩小：临路那一圈原本就不该算作绿地。乔木数上升来自公园多边形顶点结构变化后网格采样的重新命中，所有株距 / 净距校验仍 PASS，但它说明「树位采样对边界形状敏感」——这是下一次规则审查该看的点，本轮没有掩盖。

## 5. 人流与车流：受契约约束，不是独立撒点

`src/core/mobility.ts` 的 `buildMobility(doc, scene)` 是纯函数：

- **车**：沿 `RoadGraph` 做确定性节点游走，去程 + 返程形成闭合回路；车道偏移被夹紧在最小道路半宽内；路口按图连通性转弯。
- **人**：沿道路带外侧步道（两侧各一条）与**退界后的**公园/广场多边形内环运动；不进车行道、不穿建筑旋转足迹、不穿水面。路径生成时把路口连接段**显式标记**为 `segmentKind: 'crossing'`（人行横道 / 车辆转弯），校验器按段标记豁免，不靠几何半径猜测。
- **配额传导**：主干路 ×2.2、沿线建筑密度加权决定车辆配额；公园面积与周边功能决定行人配额。改公园比例，公园环线数量与人流分布会变。
- **确定性**：相位 / 速度 / 配额全部走 `sample(seed, 盐, 稳定序号)`，不用 `Math.random`、不读时钟。动画层只推进 elapsed，不进阶段 DAG、不进指纹。
- **校验分层**：`validateMobility()` 的问题写入 `scene.flowWarnings`，**不**并入 `spatial.issues`。静态城市要素的关系决定 `spatial.ok`；派生表现层的局部路径瑕疵只警告，不改判整个场景。理由与已知边界见 §6。

渲染层用两个 `InstancedMesh`（车 / 人），`useFrame` 每帧只更新矩阵；顶栏「● 流动 / ❚❚ 暂停」可开关与暂停。

### 开发期间被契约当场拦下的三个错误

1. 车道 / 步道偏移误用 `RoadSegment.w`——那是渲染矩形的 AABB 宽，不是道路真实宽度；改为从 `RoadBand.width` 取。
2. 路口转弯段被误判「闯入车行道」：先引入 9 m 半径豁免，但既有的**斜向路段 / 节点移动**测试暴露了离节点 10~21 m 的长连接段；最终改为「路径生成时显式标记 `crossing` 段 + 节点邻域半径兜底」双重判定。
3. 建筑穿越判定用 AABB 会误报；改用旋转足迹多边形 + 严格包含。
4. 只保留结构化标记时，默认场景反而冒出 40 条——原先的「0 问题」里有一部分是半径豁免掩盖的：路口 5 m 内的**沿路段**采样点确实贴进了车行道。两者必须同时生效，不能二选一。这也说明「校验口径」本身需要审查，不是改一个判定就完事。
5. 调宽步道后建筑栋数**增加**而非减少：退界变大 → 单体足迹变小 → 同样地块能塞下更多小房子。断言应写在平均占地面积上，而不是栋数。

## 6. 通行廊道规则（口径已确认：判违规并给出提示）

### 规则定义

`RELATION_MATRIX` 新增 `road → road [setbackFrom]`，校验 code `ROAD_CORRIDOR_NARROW`：

- **阈值**：`corridorMinGap() = 2 × buildingRoadClearance() = 2 × max(0.5, sidewalkWidth + 0.4)`。默认 1.8 m 步道 → **4.4 m**（两侧各一条通行带）。不新增独立旋钮：调步道宽度，阈值同步变化。
- **判定范围**：只对**近似平行**（夹角 < 约 20°）的两条独立道路带判定；交叉口（非平行）与共享端点的连通段豁免，避免把十字路口和同一条路的连续段误判为「两条过近的路」。
- **净距** = 两条有限线段最短距离 − 两带半宽之和。净距 < 阈值即写入 `spatial.issues`，`spatial.ok = false`。

### 提示（不只是标红）

每条违规带 `advice`，含：涉及的两个路段 ID、实测净距、要求净距、需移开的最小距离，以及三种可选动作（移开节点 / 删除多余路段 / 调小 `pipeline.mobility.sidewalkWidth`）。Inspector「关系」tab 有冲突卡片列出全部告警，视口 HUD 显示首条建议。

实测：`graph.node.move gn.9 → (-95, -108)` 判出 **1 条**（净距 2.43 m < 要求 4.40 m，建议移开至少 1.97 m）；默认正交路网与另外 4 组参数组合**零误报**。`corridor.test.ts` 覆盖规则登记、误报、检出、提示内容、阈值传导与几何工具。

### 已知边界（沿用）

- **静态违规判 FAIL，派生动画警告不判 FAIL**：静态城市要素（含道路带之间的关系）决定 `spatial.ok`；人流车流是派生表现层，其局部路径瑕疵仍记为 `flowWarnings`，数量、类型、坐标都可在 Inspector 看到。两者不混为一谈。
- **受影响的既有编辑场景**：`editable.test.ts` 里含该节点移动的两个用例现在会触发这条静态违规。断言改为「除廊道违规外其余空间不变量全部 PASS，且每条廊道违规都带提示」——**没有通过改编辑数据来回避**。
- **步道与车行道的规则写法**：人不得**沿**车行道行进，但与道路近垂直的横穿（含斜交路口过街）合法。校验按路径方向与道路方向夹角判定，并对路口连接段用 `segmentKind = 'crossing'` 标记豁免。开发过程中先试过固定半径、后试过纯段标记，两种都有漏判/误判，最终是两者叠加 + 方向判定。

- **地块红线仍压在道路带内**，这是 v1.2.0 的历史口径。本轮没有改红线，而是让所有「用地类要素」统一从道路带退让。若要改红线口径，会牵动面提取、面积守恒和全部既有验收，属于独立改造。
- **公园退界用半平面裁剪**，只裁临路一侧、背街侧不动；凹多边形被裁后若自交会跳过该绿地（`setbackFromRoads` 返回 null）。默认场景未触发，但极端参数下可能少一块绿地。
- **车流不模拟交通**：没有信号灯、没有跟驰、没有避碰，车辆之间会重叠。这是「流动表现」不是「交通仿真」；若要做交通仿真，需要独立的 agent 规则与时序模型。
- **行人不进建筑内部**，也不表达「从建筑出入口进出」；当前只沿步道与开放空间网络运动。
- **高程场仍未回填到 Y 坐标**（E2 遗留），流动代理都在 `y≈0.7~0.9` 的平面示意层。
- `parkLoop` 对凹多边形用「顶点向质心收缩 15%」，极端凹形可能产生跨外部的弦；当前参数与实测场景未触发。

## 7. 复现

```bash
npx vite-node scripts/diagnose-spatial.ts   # 逐图层重叠实测 + 流动校验统计
npm test                                    # relations.test.ts / mobility.test.ts 覆盖不变量
npm run dev                                 # 顶栏可开关人流车流
```

规则本身在 `src/core/spatialRules.ts` 的 `RELATION_MATRIX`，`describeRelations()` 可导出为文本供 Inspector 或外部文档消费。
