## 0. 三条已确认并落地的口径

| # | 议题 | 结论与落地 |

## 1. 总体视觉定位

**一句话**：阳光充足的普通街区，像一张可以走进去的动画背景画——不是未来城市，不是效果图，是「有人刚刚在这里生活过」的日常切片。

**三条铁律**（冲突时按此排序）：

1. **轮廓优先** —— 先保证远看剪影可读、近看边线稳定，再谈材质。
2. **色块优先** —— 用大色块与明度分层建立体积，不靠纹理与高光。
3. **生活痕迹优先** —— 细节密度服务于「谁在这里、在做什么」，不服务于「看起来很精细」。

**气质参照**（取气质，不复刻任何具体作品）：日本日常系动画的背景美术、昭和/平成下町的沿街小店、北欧小镇的低饱和木构；**排除**：赛博朋克、未来都市、纪念性广场、主题乐园式夸张。

**尺度参考（可选，不是落地面前提）**

按本轮决定，**默认规则一律不动**。下表保留为「若之后想要更彻底的日常街区」时的调参参考，全部通过既有字段或本轮新增的自定义功能占比即可完成，不需要改代码：

| 项 | 现值 | 日常街区参考值 | 理由 |
|---|---|---|---|
| `height.base / max` | 18 / 165 m | 12 / 24 m | 4–6 层为主，行人尺度可感知 |
| `height.profile` | `centerHigh` | `uniform` + 轻微 `jitter` | 取消 CBD 天际线 |
| `height.taper` | 1.35 | 0.4 | 中心不再拔高 |
| 功能占比 | preset `balanced`（office .34 最高） | 住宅 .34 / 商业 .28 / 办公 .18 / 研发 .20 | 生活功能主导；用 `mixMode=custom` 调节 |
| `pipeline.parcels.targetSize` | 20 m | 14–18 m | 沿街小开间，立面节奏密 |
| `pipeline.landUse.parkRatio` | 0.12 | 0.16 | 口袋绿地穿插 |
| `pipeline.mobility.vehicles / pedestrians` | 72 / 140 | 36 / 180 | 步行城市，车是配角 |

功能占比现在有**目标 / 实际对照**：Inspector「统计」页显示四类可建功能的目标权重与实际地块占比，命令面板提供「住宅主导 / 沿街商业 / 回到预设」三个预设，可直接验证调节是否传导到 `landUseCounts`、构件装配与空间校验。

## 2. 色彩：高明度、低饱和、色相分工

### 2.1 统一规则

- **明度分布 70 / 20 / 10**：70% 高明度基底（L ≥ 78%）、20% 中间调结构、10% 高饱和点缀。
- **饱和度上限 45%**（点缀色除外），全城共享这一条，避免「每栋一个颜色」的糖果城。
- **阴影不是变黑**：阴影 = 基色向冷蓝紫 `#8FA6BE` 偏移约 22%，保持彩度与透明感。这是三渲二与 PBR 最本质的区别。
- **点缀色只允许出现在「生活信息」上**：招牌、门头、遮阳棚、邮筒、贩卖机、交通标识。建筑本体不出现高饱和。

### 2.2 主色板（可直接替换 `stages.ts::PALETTES` 与 `CityScene.tsx::THEME`）

| 类别 | 色值 | 用途 | 对应现有字段 |
|---|---|---|---|
| 天空 / 背景 | `#E8F1F4` | 视口底色、雾 | `THEME.bg` |
| 地面 / 铺装 | `#EDE7DA` | 场地、人行道 | `THEME.ground` |
| 路面 | `#D9D4C8` | 车道 | `THEME.roadMain / roadMinor` |
| 建筑共通底 | `#F2EDE2` | 所有建筑基色（奶白） | `PALETTES` 基色 |
| 结构线 / 外轮廓 | `#4A4640` | 描边、檐口、层间线 | 新增 outline 色 |
| 亮面 | 基色 `+8%` L | 受光面 | toon ramp step 1 |
| 中间调 | 基色原值 | 主体 | toon ramp step 2 |
| 阴影面 | 基色 → `#8FA6BE` 偏 22% | 背光面、投影 | toon ramp step 3 |
| 高光 | `#FFF6E2` | 仅玻璃/金属小块 | 非 PBR 高光 |

## 3. 光影：固定时间、三值阶梯、硬边投影

| 项 | 设定 |
|---|---|
| 时间 | **固定「晴日上午 10:00」**，不做昼夜/天气切换。色板与轮廓的稳定性优先于动态。 |
| 主光 | 单一平行光，方位 225°（西南）、仰角 48°，色 `#FFF4DC` 暖白，强度 1.0 |
| 补光 | 半球天空光 `#BBD8EE` / 地面反弹 `#EDE7DA`，强度 0.45 |
| 明暗分层 | 量化 `N·L`：`> 0.65` 亮面 / `0.28–0.65` 中间调 / `< 0.28` 阴影；过渡带 ≤ 0.02（几乎硬边） |
| 投影 | 硬边 + 极轻微软化（1–2 px），颜色偏 `#8FA6BE`，接地处加深；**不用 PCF 软阴影** |
| AO | 只用于接地、檐下、凹角，强度 ≤ 0.25，不铺满立面 |
| 高光 | 只在玻璃、金属招牌、车顶出现，**块状单色**，不使用 PBR 粗糙度/金属度连续渐变 |
| 雾 | 远景淡蓝 `#DCEBF0`，仅降低远景轮廓对比，**不改变色相** |

> 现状 `directionalLight` + `ambientLight` + `hemisphereLight` + `meshStandardMaterial` 是连续光照。要实现上面这套，必须换成 toon ramp 材质（见 §9 P0）。

## 4. 材质：三层封顶，细腻但简洁

**每栋建筑最多 3 个材质层 + 1 个装饰层**，超出即视为过度设计：

| 层 | 内容 | 实现 | 允许的复杂度 |
|---|---|---|---|
| L1 基底 | 墙面大色块 | 纯色 / 1D ramp 贴图 | 无纹理或极弱纸纹 |
| L2 结构 | 窗格、窗框、层间线、檐口 | 共享 atlas + 模块化 UV | 全城 3 套窗格模数 |
| L3 体积 | 屋顶、阳台、雨棚的明暗面 | toon 三值 | 不叠法线贴图 |
| L4 装饰 | 招牌、门头、生活物件 | 独立实例层 | 按功能配额，见 §7 |

- **统一模数**：开间 `3.2 m`、层高 `3.0 m`、窗 `1.4 × 1.6 m`、窗台 `0.9 m`。所有功能共用，靠组合方式区分，不另起一套比例。
- **一张共享贴图 atlas**：UV 按模数平铺，避免每栋独立贴图与材质切换。
- **禁止**：PBR 粗糙度/金属度微调、脏污/做旧/划痕贴图、法线贴图堆细节、程序化噪声铺满墙面。
- 「细腻」来自 **L2 的窗格节奏 + L4 的生活信息**，不来自贴图分辨率。

## 5. 轮廓：稳定、恒定宽度、深暖灰

| 项 | 设定 |
|---|---|
| 颜色 | 外轮廓 `#4A4640`（深暖灰，**非纯黑**）；内轮廓 `#6B655C` 细一档 |
| 宽度 | 屏幕空间恒定 `1.5 px @1080p`（外）/ `0.8 px`（内），远景不消失、只降对比 |
| 实现 | **几何法**：背面挤出（inverted hull）+ 深度偏移。不要用法线/深度边缘检测——视角一转线就抖，违反「清晰稳定」 |
| 内轮廓位置 | 只描结构转折：檐口、层间线、窗洞外框、体块交接；**不描每块砖、不描每扇窗中挺** |
| 遮挡 | 描边 `depthTest` 开，被前景正确遮挡；选中高亮沿用现有 wireframe box，不混进风格描边 |
| 远景 | 距离 > 300 m 时轮廓对比降至 60%，保证空气感但不丢可读性 |

> 工程代价：`InstancedMesh` 的描边需要**第二组同矩阵实例**（背面材质）或后处理全屏 pass。前者多 1× draw call/类，后者需要 normal+depth buffer。这是 P0 里最贵的一项，见 §9。

## 6. 场景氛围：生活化不是「加很多东西」

**核心方法**：生活物件必须**成组、有归属、有叙事**，而不是均匀撒点。

| 载体 | 成组规则 | 典型物件 |
|---|---|---|
| 住宅沿街 | 每 2–3 个开间一组 | 阳台晾衣、花盆、空调外机、自行车、门帘、信箱 |
| 商业沿街 | 每店一组，招牌必须朝路 | 门头招牌、遮阳棚、陈列架、立牌、自动贩卖机、暖帘 |
| 办公沿街 | 每栋 1–2 处，克制 | 入口雨棚、铭牌、行道树池、旗杆 |
| 交通节点 | 每个路口 / 站台一组 | 站牌、候车亭、信号灯、自行车架、导向标识、邮筒 |
| 休闲空间 | 每 200 m² 一组 | 长椅、饮水台、亭子、垃圾桶、树池、儿童设施 |

- **密度预算**：每 100 m 街道 12–18 件生活物件，**其中至少 1 件是"不整齐"的**（歪的花盆、半拉的帘子），否则会像样板间。
- **人车流动**（已有 `mobility`）：行人保持正常人体比例、简化面部（不 Q 版），配色从点缀色取，与建筑色分离；车辆圆角、低饱和、无反光。
- **植被**：团块状树冠 3 色阶，不用透明贴图叶片；行道树按 `streetInterval` 等距但冠幅按种子微变。
- **留白**：街道必须有"空"的段落。生活物件连续铺满 = 主题乐园，不是日常。

## 7. 按功能区分建筑细节规则（核心）

### 7.1 与现有数据结构的映射（重要）

| 目标功能 | 现有 `LandUseId` | 现有 `ArchetypeId` | 缺口 |
|---|---|---|---|
| 住宅 | `residential` | `slab` / `incubator` | 无阳台/窗格/屋顶坡面 |
| 商业 | `commercial` | `podium` / `incubator` | 无门头/招牌/棚 |
| 办公 | `office` / `research` | `tower` / `slab` / `research` | 需降层高，去掉塔楼原型 |
| **交通** | **无** | **无** | **项目没有交通建筑**，见下 |
| **休闲** | `park` / `plaza`（纯地面多边形） | **无** | **没有休闲建筑** |

**两条路，建议先走轻量版：**

- **轻量（P2 推荐）**：不新增 `LandUseId`，把交通/休闲做成**设施实例层**——交通挂 `scene.roadEdges`（候车亭/站牌/信号灯），休闲挂 `scene.parks[].polygon`（亭/长椅/树池）。改动集中在 `CityScene`，不碰 schema/校验/指纹。
- **完整（P3）**：新增 `LandUseId: 'transit' | 'leisure'` 与 `ArchetypeId: 'station' | 'pavilion'`，需要同步改 `types.ts` / `schema.ts` 白名单 / `fields.ts` / `stages.ts` 的 `ARCHETYPE_BY_USE` / `MIX_WEIGHTS` / `validate.ts` / 测试。成本约 4–6 个文件 + 迁移，不属于 MVP。

### 7.2 五类建筑规则表

| 维度 | 住宅 | 商业 | 办公 | 交通 | 休闲 |
|---|---|---|---|---|---|
| **造型识别** | 4–6 层板楼，坡屋顶或平顶带女儿墙，重复开间 | 1–3 层沿街小体量，首层通透、大开口 | 5–8 层规整矩形，水平带窗，无装饰 | 低矮横向体量 + 大挑檐 / 站棚 | 1–2 层坡顶小屋、亭、廊 |
| **细节密度** | **中**（每立面 8–14 件） | **高**（每立面 14–22 件） | **低**（每立面 4–6 件） | **中低**（标识优先，6–8 件） | **中低**（构件少、材质温润，5–8 件） |
| **重复 vs 变异** | 模数重复 + 每层 1–2 处个体变异（晾衣/花盆/帘色） | 逐店不同，招牌宽度/朝向按开间取 | 严格重复，**不允许个体变异** | 全线统一制式 | 手作感，允许不对称 |
| **招牌规则** | 无商业招牌；仅门牌、信箱 | **必须有**，每开间 1 块，朝路，尺寸 ≤ 开间 0.8，高 ≤ 1.2 m，只用点缀色 | 仅入口铭牌，1 处/栋 | 导向标识，蓝绿 `#4E7E96`，尺寸统一 | 木牌手写感，1 处/亭 |
| **色彩** | `#E8C9A0` + 陶瓦 `#C87F5C` | `#F0D8C0` + 木 `#B98A5E` + 朱/黄点缀 | `#DCE6E8` + `#A9B9BC` | `#DCE3D8` + `#4E7E96` | `#D5E4C4` + 木 `#B98A5E` |
| **材质层** | L1+L2+L4（阳台、栏杆、窗框） | L1+L2+L3+L4（棚、招牌、陈列） | L1+L2（仅窗格与分缝） | L1+L3（大挑檐明暗） | L1+L3（木构、瓦面） |
| **环境物件** | 晾衣、盆栽、自行车、外机、门帘 | 遮阳棚、立牌、贩卖机、暖帘、陈列箱 | 树池、旗杆、入口雨棚 | 站牌、候车亭、信号灯、车架、邮筒 | 长椅、饮水台、垃圾桶、树池 |
| **轮廓处理** | 外轮廓 + 阳台/檐口内线 | 外轮廓 + 招牌边框 + 棚沿 | 外轮廓 + 层间线，**不加窗框描边** | 外轮廓 + 挑檐边线 | 外轮廓 + 坡顶折线 |
| **代码落点** | `ARCHETYPE_BY_USE.residential` → `slab` 扩展立面模块 | `commercial` → `podium` + 招牌实例层 | `office/research` → `slab/research`，移除 `tower` 权重 | 新增 `streetFurniture` 实例层 | 新增 `parkFurniture` 实例层 |

### 7.3 统一性约束（防止五类各自跑偏）

无论哪类，全部强制：

1. 同一套 §2 色板，饱和度 ≤ 45%；
2. 同一轮廓色 `#4A4640` 与恒定屏幕宽度；
3. 同一 toon 三值光照与主光方向；
4. 同一 `3.2 m` 开间 / `3.0 m` 层高模数；
5. 同一张共享 atlas，不出现功能专属贴图集；
6. **细节密度差只允许体现在 L4 装饰层与内轮廓数量**，不允许改变 L1/L2 的色块逻辑。

## 8. 需要避免的表现倾向

| # | 倾向 | 为什么错 | 替代做法 |
|---|---|---|---|
| 1 | 赛博朋克霓虹、冷蓝玻璃幕墙、165 m 塔楼 | **就是当前默认场景**，与「日常」正相反 | 降层高、暖色板、取消中心高剖面 |
| 2 | 写实 PBR、脏污做旧、HDR 高对比 | 连续光照会摧毁三值阶梯与稳定色块 | toon ramp + 固定主光 + 有限 AO |
| 3 | 纯黑粗描边、法线边缘检测 | 视角一动线就抖，且黑色压死高明度画面 | 深暖灰 `#4A4640`、几何挤出、屏幕空间恒宽 |
| 4 | 全城高饱和 / 每栋一个颜色 | 变成糖果城，失去统一空气感 | 70/20/10 明度分布，点缀色只给生活信息 |
| 5 | 所有建筑同样细节密度 | 视觉噪音，功能不可辨识 | 按 §7.2 密度梯度：办公最低、商业最高 |
| 6 | 生活物件均匀撒点 | 像贴图填充，没有叙事 | 成组、有归属、留出空段、至少一处「不整齐」 |

| 8 | 动态昼夜 / 天气 / 随机色温 | 色板与轮廓稳定性被破坏 | 固定上午 10 点晴天；如需变化，另做预设并重新校准 ramp |
| 9 | 每栋独立贴图 / 材质 | 破坏 7 类各 1 个 draw call，2 km 场景不可控 | 一张共享 atlas + 模块化 UV + 实例色 |
| 10 | 过度 Q 版、夸张头身比、圆润倒角一切 | 与「高精细建模」自相矛盾 | 正常比例、简化面部、构件精细但形体克制 |

### 9.3 风险清单与当前处置

1. **draw call**：`everyday` 下只增加 2 个 InstancedMesh（构件层、建筑描边），远低于原估计的 20+ 类；未采用「按构件类型分组」，而是所有构件共用同一 box 原型 + 实例色。
2. **toon × instanceColor**：使用 `MeshToonMaterial` 而非自定义 shader，three 自动注入 `USE_INSTANCING_COLOR`，`setColorAt()` 的功能色不丢。
3. **描边 × InstancedMesh**：背面挤出确实使建筑实例翻倍，但只有一组额外 mesh；2,500 栋场景的帧率尚未实测（见 §10 未勾选项）。
4. **生成性能**：构件装配是渲染层纯派生，`limit=16000` 上限保护，实测耗时见 `npm run bench` 与工作日志；2 km 场景的构件会触发截断，属预期降级。
5. **确定性契约**：全部走 `sample(seed, 盐, 稳定序号)`，`facadeKit.test.ts` 验证同一 `(scene, seed)` 逐位一致；构件层不进指纹。
6. **主题解耦**：`toggleSceneTheme` 只改 React state 与 localStorage，`SceneDocument` 与 `generateScene()` 均不参与，168 个既有用例的指纹不变性成立。

## 11. v1.1 落地实测（2026-11-15）

上机实测数据（`npx vite-node` 调用 `generateScene` + `assembleFacadeKit`，400 m 默认场地）：

| 场景 | 四类功能地块（办公/住宅/研发/商业） | 构件总数 | 窗格 | 招牌 | 阳台 | 装配耗时 | 空间校验 |
|---|---|---|---|---|---|---|---|
| 默认 preset `balanced` | 50 / 46 / 38 / 33 | 2,973 | 1,396 | 81 | 105 | 11 ms | PASS |
| 住宅主导（res .85） | 7 / **139** / 9 / 12 | 3,388 | 1,462 | 38 | **331** | 5 ms | PASS |
| 商业主导（com .9） | 6 / 4 / 3 / **154** | 3,738 | 1,110 | **426** | 4 | 6 ms | PASS |

三组均无构件截断、生成耗时 223–331 ms。这组数据说明两件事：

1. **占比调节不只是改数字** —— 它一路传导到 L4 装饰层，住宅主导时阳台 ×3.2、商业主导时招牌 ×5.3，视觉气质随之改变，这正是「城市是一个整体」在表现层的对应。
2. **构件层不是性能瓶颈** —— 全部构件共用同一 box 原型，装配 5–11 ms、`everyday` 下只增加 2 个 draw call；瓶颈仍在 PCG 生成（2 km 实测 6.6 s），与风格层无关。

复现命令：`npm test`（189 用例）、`npm run bench`（生成性能）、顶栏「☀ 日常场景 / ▤ 制图场景」切换主题。
